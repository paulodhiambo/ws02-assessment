# JamiiCoreBankingProduct (API Product, 1.0.0)

Bundles one operation from each API into a single subscribable product:

| Operation                                | From API                 |
|------------------------------------------|--------------------------|
| `GET /{accountNumber}/balance`           | JamiiAccountsAPI v1      |
| `GET /{customerId}`                      | JamiiCustomersAPI v1     |
| `POST /eligibility`                      | JamiiLoanEligibilityAPI v1 |

- Gateway context: `/jamii/core` (default version; `/jamii/core/1.0.0` also works), e.g. `GET /jamii/core/0100000001/balance`
- Tier: **Gold** (one quota across the bundle)
- Security: OAuth2 **or** API key

**Why a product:** first-party channels (mobile, internet banking) need all
three APIs. One subscription gives them one set of keys and one quota, and
the individual APIs stay subscribable on their own tiers for narrower
consumers, e.g. a partner that only needs loan eligibility.

`Definitions/swagger.yaml` is the merged definition generated by API Manager
from the three API definitions. Regenerate it by exporting the product
(`apictl export api-product -n JamiiCoreBankingProduct -v 1.0.0 -e dev`)
rather than editing by hand.

`scripts/deploy-apim.sh` imports the product only after all three APIs have
imported successfully.
